# ADR 0005：编辑器岛桥接协议 v1

- **状态：** 已接受
- **日期：** 2026-11-05
- **决策者：** 架构组
- **相关：** SRS-M3STUDIO-001 V4.1 §6.4、NFR-039、DC-032、ADR 0001

## 背景

宿主与编辑器岛必须跨 iframe/窗口边界通信，并满足：

- 单屏隔离：消息只针对一个 `screen_id`。
- 保存安全：必须带 `base_version`，冲突时不能覆盖。
- 草稿不丢：超时、重连、冲突时保留最后一次 `change`。
- 安全：校验来源、消息大小、协议版本。
- 可测试：不依赖浏览器即可验证状态机。

## 决策

1. 协议标识：`protocol:"m3studio/editor@1"`，`version:1`。
2. 每条消息必须带 `protocol`、`request_id`、`screen_id`、`type`、`payload`。
3. 宿主 → 岛消息：`load/theme/mode/flush/fit/preview`。
4. 岛 → 宿主消息：`ready/change/save/select/preview/error/dirty`。
5. 状态机：`idle → loading → ready → dirty → saving → saved`；异常态 `conflict/stalled/error/closed`。
6. 宿主侧会话负责：
   - 版本检查：`base_version !== savedVersion` → `BRIDGE_CONFLICT`，保留草稿；
   - 超时：`loading/saving` 超过 `timeoutMs` → `stalled`；
   - 重试：`stalled` 时重发最后一次 `load`，草稿保留；
   - 安全：校验 `event.origin` 与 `event.source`；
   - 大小：单条消息 ≤ 5MB。
7. 岛不得直接调用 API、不得直接写文件、不得接收项目级密钥或其他屏正文。
8. 保存成功后宿主返回新版本号；失败返回稳定错误码。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 岛直接调用 REST API | 不采用 | 权限、隔离、版本校验会被绕过 |
| 共享同一 DOM / 同源直接调用函数 | 不采用 | 无法隔离运行时，编辑器升级会影响宿主 |
| 只传 HTML/截图 | 不采用 | 无法做结构化保存、版本与 FlowEdge 投影 |
| `postMessage` 协议 + 宿主状态机 | **采用** | 边界清晰、可测试、可独立部署 |

## 后果

**正面**

- 协议与状态机可纯 Node 测试。
- 冲突/超时/重连行为确定，不会静默丢稿。
- 岛可替换，不影响宿主治理。

**负面 / 代价**

- 需要协议版本管理；不兼容时明确失败而不是降级。
- 大文档需分片或文件通道（M1 细化）。
- 宿主与岛需共享 `ScreenDoc` schema 版本。

## 约束

- 错误码：`BRIDGE_PROTOCOL_MISMATCH`、`BRIDGE_TIMEOUT`、`BRIDGE_CONFLICT`、`SWIPE_DIRECTION_REQUIRED` 等。
- `save` 的 `doc` 必须通过 `validateScreenDoc`。
- `change` 只更新草稿，宿主不立即落库。
- `ready` 的 `version` 必须等于 `BRIDGE_VERSION`。

## 验证

- `tests/m3-editor-bridge.test.mjs`：协议字段、方向、必填、状态机、冲突、超时、重试、选区、预览、安全与大小上限。
- `docs/编辑器岛桥接协议.md`：消息表、状态机、错误码、示例。
