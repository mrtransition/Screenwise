# ADR 0004：主题在项目级维护，版本快照携带主题与 Prompt 摘要

- **状态：** 已接受
- **日期：** 2026-11-05
- **决策者：** 架构组
- **相关：** SRS-M3STUDIO-001 V4.1 §5.1、§5.2、§5.4、§10、DC-031/DC-041

## 背景

M3E 的主题（palette、dark、contrast、shape、font、motion、emphasized）是项目级配置，影响所有屏幕。`prd-diy` 的版本是单屏快照。若主题只存当前值：

- 回滚旧屏幕版本时，无法还原当时的主题。
- 导出旧版本会得到“旧内容 + 新主题”的错误结果。
- 主题变更若递增每个屏幕版本，会产生大量无意义版本。

## 决策

1. 主题只在项目级维护：`ProjectDesign.theme` 是权威；`design_tokens` 是派生投影。
2. 屏幕只允许 `frame.bg` 覆盖背景色，不允许覆盖其他主题角色。
3. 主题变更记录到 `design-revisions.json`，**不递增屏幕版本号**。
4. 每个屏幕版本快照携带：
   - `theme_snapshot`：该版本创建时的完整主题；
   - `prompt_digest`：该版本对应 Prompt 的摘要/哈希，可为哈希，不要求完整 Prompt。
5. 导出、分享链接、预览必须使用版本快照中的 `theme_snapshot`，而不是当前主题。
6. 分享链接必须带 `schema` 与 `format`，读取时校验（DC-034）。

## 备选方案

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 主题存每个 `ScreenDoc` | 不采用 | 复制严重，主题无法统一，项目级变更需改所有屏 |
| 主题只存当前值 | 不采用 | 旧版本无法重放，导出不一致 |
| 主题变更递增所有屏幕版本 | 不采用 | 版本爆炸，且违反“主题变更不属于屏幕内容变更” |
| 项目级主题 + 版本 `theme_snapshot` | **采用** | 兼顾统一主题与历史可重放 |

## 后果

**正面**

- 回滚/预览/导出可精确重放当时视觉。
- 主题调整不会污染屏幕版本历史。
- Prompt 与视觉版本可追溯。

**负面 / 代价**

- 每个版本快照体积增加（主题对象很小）。
- 需要项目修订记录与屏幕版本两套历史。
- `prompt_digest` 的生成时机与算法需固定（建议 SHA-256，前缀 `sha256:`）。

## 约束

- `theme_snapshot` 必须通过 `validateTheme`。
- `prompt_digest` 为字符串或 `null`；不得存完整 Prompt。
- `design_tokens` 不得作为权威来源；可由 `theme + customPalette` 重建。
- 主题变更必须写 `ProjectRevision`，包含 `revision/created_at/actor/change_summary/design/design_tokens`。

## 验证

- `tests/m3-schema.test.mjs`：版本快照必须带 `theme_snapshot`，`prompt_digest` 类型校验。
- `tests/m3-import-export.test.mjs`：主题随项目往返。
- 既有 `tests/isolation.test.mjs`：改 A 屏不影响 B 屏。
