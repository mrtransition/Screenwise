## 1. 引言

### 1.1 目的

定义本工具的功能需求、非功能需求、数据约束、接口契约与验收标准。本文档是研发、测试与验收的唯一需求基线；凡与本文档冲突的实现，以本文档为准；凡标注“未实现”或“规划”的能力，不得在当期验收中作为缺陷提出，如需纳入须另行立项。

### 1.2 产品定位

面向产品经理、设计师与前端原型人员，以**屏幕**为最小独立单元：

> AI 每次只生成或修改一张屏幕，屏幕之间在生成阶段完全隔离；屏幕内容完成后，再通过独立的**关联层**把屏幕连成可点击原型。

进阶方向进一步强化：**人工直接编辑与 AI Patch 并列为一等变更来源；确定性文字修改优先走内置生成器，减少大模型 token 消耗；人工与 AI 变更冲突时三方合并、不静默覆盖。**

### 1.3 核心业务目标

| 编号   | 业务目标                                                | 状态                 |
| ------ | ------------------------------------------------------- | -------------------- |
| BR-001 | 单屏独立生成：一次只写目标屏                            | 已实现               |
| BR-002 | 编辑隔离：改 A 屏不影响 B 屏的内容、版本与关联          | 已实现（自动化断言） |
| BR-003 | 增量修改：修改类任务优先输出局部 patch                  | 已实现               |
| BR-004 | 后置关联：建边不触发任何屏幕重生成                      | 已实现               |
| BR-005 | 可回滚：版本快照 + 单屏回滚                             | 已实现               |
| BR-006 | 可预览、可导出：关联后能点着走通并可离线分发            | 已实现               |
| BR-007 | 人工编辑一等来源：空间编辑与 AI Patch 并列进入版本树    | 规划（未实现）       |

### 1.4 范围

**已实现能力（V2.0 基线）：**

- 单项目多屏幕的无限画布管理（创建、复制、重命名、排序、删除、拖拽定位）；
- 单屏 AI 生成（整屏 / 区域 / 组件三种范围）与局部 patch 修改；
- 待确认 → 接受 / 拒绝的落库闸门，版本快照、回滚、撤销、版本对比；
- 屏幕锁定、只读成员权限校验；
- 全局 AI 模型目录（内置生成器 + OpenAI 兼容模型），含连接测试与输出归一化；
- 手动拖拽建边、一句话建边（候选边需确认）、边属性编辑与删除、孤儿边标记；
- 应用内预览（跳转 + 返回栈）；
- 导出单文件静态原型，离线可点；
- 审计日志、跨屏越权告警。

**明确不做（本期边界）：**

- 多人实时协作与登录态鉴权（仅 header 记录操作者）；
- 条件分支、变量系统、弹层页；
- 节点分组、组件库与组件级复用；
- 生产级代码生成（导出的是可运行 HTML 原型，不是工程代码）。

**进阶规划（未实现，不参与当前验收）：**

- 空间编辑：画布上直接修改简单文字、图标与简单属性；
- 确定性变更路由：显式结构化指令 / 规则匹配 / 轻量分类器短路大模型；
- 内置生成器处理可唯一确定变更值的文字修改；
- 三方合并与冲突治理：人工编辑与 AI Patch 冲突不自动吞并；
- 版本来源标记与单屏版本树：`manual_direct` / `builtin_rule` / `ai_patch` 并列。

### 1.5 术语

| 术语            | 定义                                                                                                 |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| 屏幕 / Screen   | 原型中的一张独立页面，唯一 `screen_id`，形如 `scr_xxxxxxxxxxxx`                                      |
| 节点树 / doc    | 屏幕内容存储形式：`{ version, root }`，节点含 `id / type / tag / props{style,attrs,text} / children` |
| 节点 id         | 屏内唯一且稳定标识，patch 只按 id 定位                                                               |
| Patch           | 局部变更集，`ops[]` 每项声明操作类型、目标、值                                                       |
| 热区 / Hotspot  | 页面内带 `data-anchor` 属性的可点击元素，流程层唯一依赖                                              |
| FlowEdge        | 屏幕跳转关系，独立文件存储，只含 `screen_id` + `hotspot_id`                                          |
| pending         | 已生成但未接受的候选结果，不占版本号                                                                 |
| 孤儿边 / orphan | 边引用的源屏、目标屏或热区已不存在，边保留但标红                                                     |
| 设计 token      | 跨屏唯一共享物（颜色、圆角、字号、字体族）                                                           |
| 空间编辑        | 用户在画布上直接修改屏幕内简单文字、图标或简单属性                                                   |
| `change_source` | 版本来源标记：`manual_direct` / `builtin_rule` / `ai_patch`                                          |
| 内置生成器      | 确定性、无网络、恒可用的生成路径，处理可唯一确定变更值的请求                                         |
| 意图路由        | 在大模型调用前判断请求走显式短路、规则、轻量分类器还是大模型                                         |
| 三方合并        | 以人工编辑与 AI Patch 的共同祖先版本为 base，逐字段比对合并                                          |
| keep 标记       | 锚定人工修改节点的保护标记，AI 请求上下文携带该约束                                                  |

## 2. 总体描述

### 2.1 用户角色与权限

| 角色                                | 可做                             | 不可做                             |
| ----------------------------------- | -------------------------------- | ---------------------------------- |
| owner / editor（默认 `local-user`） | 全部读写                         | —                                  |
| readonly                            | 查看项目、屏幕、版本、预览、导出 | 任何写操作返回 403 `NO_PERMISSION` |

- 角色来自 `project.members[]`（`{ user, role }`），未登记成员视为可写（本地单用户前提）。
- 所有写接口统一走 `assertWriter(pid, actor)`，**服务端校验**，前端置灰只是辅助。
- 当前没有成员管理接口；新增/编辑成员需直接改 `project.json`。
- 进阶规划中，空间编辑与内置生成器写接口同样走 `assertWriter`，并受锁定校验。

### 2.2 系统组成

```
浏览器（原生 ESM，无构建）
├─ main.js      三种工作态：画布 / 关联 / 预览 + 各类弹窗
├─ canvas.js    无限画布、节点、热区层、连线绘制
├─ render.js    节点树 → HTML（画布 iframe 与预览共用）
└─ styles.css
服务端（Node ≥ 20，零依赖）
├─ app.js       REST 路由 + 静态资源
├─ service.js   业务规则：隔离 / 锁定 / 权限 / 版本 / 审计
├─ domain/      doc.js（节点树）、patch.js（校验与应用）
├─ ai/          context.js（隔离闸门）、provider.js、normalize.js、local.js、models.js
├─ store/       fs.js（原子写 + KeyedQueue）、repo.js（仓储与版本提交）
└─ export/      static.js（导出自包含 HTML）
```

**进阶规划组件（未实现）：**

```
├─ space-editor/  空间编辑提交、编辑态本地暂存、锁定拦截
├─ router/        显式短路、规则匹配、轻量分类器、危险降级防护
├─ merge/         三方合并、冲突 UI 数据、keep 标记
└─ provenance/    版本来源、路由层级、成本标记
```


## 6. 接口需求

### 6.1 通用约定

- 前缀 `/api`，返回 `{ ok: true, data }` 或 `{ ok: false, error: { code, message, detail? } }`。
- 错误 `detail.hint` 在所有 422 上必须给出可照做的下一步。
- 写操作记录 `actor`（来自 `x-proto-user`，缺省 `local-user`）并写审计。
- 进阶写接口同样必须携带操作者身份与项目权限；路由服务响应回显 `route_layer` 与是否调用大模型。

### 6.4 错误码

| HTTP | code                               | 含义                                   | 屏幕是否变化 |
| ---- | ---------------------------------- | -------------------------------------- | ------------ |
| 400  | `BAD_REQUEST`                      | 参数不合法                             | 否           |
| 400  | `EDIT_SCOPE_REQUIRED`              | 缺 `edit_scope` 或取值非法             | 否           |
| 400  | `SELECTION_REQUIRED`               | 区域/组件范围未提供选区                | 否           |
| 400  | `SELECTION_NOT_FOUND`              | 选区节点不在当前屏                     | 否           |
| 400  | `HOTSPOT_NOT_FOUND`                | 热区不在源屏                           | 否           |
| 400  | `EDGE_PARSE_FAILED` / `NO_HOTSPOT` | 一句话建边解析失败                     | 否           |
| 403  | `NO_PERMISSION`                    | 只读成员执行写操作                     | 否           |
| 403  | `FORBIDDEN_TARGET`                 | 跨屏写入，已拦截并告警                 | 否           |
| 404  | `NOT_FOUND`                        | 项目/屏幕/版本/边/模型不存在           | 否           |
| 409  | `CONFLICT`                         | 存在 pending、已有生成中、无可撤销版本 | 否           |
| 409  | `STALE_PENDING`                    | pending 基于的版本已过期               | 否           |
| 409  | `EDGES_EXIST`                      | 删除有边的屏幕未指定处理方式           | 否           |
| 422  | `INVALID_OUTPUT`                   | 模型输出违反结构契约                   | 否           |
| 422  | `UNPROCESSABLE`                    | 未识别出可执行的修改                   | 否           |
| 423  | `SCREEN_LOCKED`                    | 屏幕已锁定                             | 否           |
| 502  | `MODEL_FAILED`                     | 模型调用失败/超时/输出截断/结构缺 root | 否           |

**进阶新增错误码（规划）：** `ROUTE_AMBIGUOUS`（路由无法唯一确定，升级大模型）、`MERGE_CONFLICT`（三方合并存在冲突，需用户处理）、`EDIT_OUT_OF_SCOPE`（空间编辑超出支持范围）。`SCREEN_LOCKED` 复用。

## 9. 关键设计取舍与风险

### 9.1 已实现基线取舍

| 主题                         | 取舍                                       | 理由                                                    |
| ---------------------------- | ------------------------------------------ | ------------------------------------------------------- |
| 版本用快照而非 diff 链       | 单屏多留几十个版本，每版整文件             | 回滚只是切指针，绝不波及他人，任意版本可独立打开        |
| patch 判据用“屏幕是否有内容” | 而非 `edit_scope`                          | `scope=screen` 只代表“允许整屏重写”，不代表每次都要重写 |
| 热区标识写在页面里           | `data-anchor` 由页面声明，关联层只引用名字 | 页面重生成后同名热区连线自动继续有效                    |
| 孤儿边不自动删除             | 只标记、变红                               | 连线是用户资产，应由人决定                              |
| 生成只写 pending             | 接受才落库                                 | 模型不可靠时，用户永远是最后一道闸门                    |
| 导出单文件内联               | 全部屏打在一个 HTML                        | 免依赖、易分发；屏多时体积增大                          |

## 10. 状态机附录

**Screen.status：**

```
draft ──生成中──> generating ──成功──> pending ──接受──> applied
  ↑                  │                   │
  │                  └──失败──> draft/applied
  └──────────── 拒绝 ◄──────────────┘
任意状态 ──锁定──> locked ──解锁──> applied（有内容）/ draft（仅空屏基线）
```

**GenerationJob.status：** `generating → pending_confirm → applied | rejected | failed | no_op`

**FlowEdge.status：** `candidate → confirmed → 删除`

**Pending 生命周期：** 生成即创建（带 `base_version`）→ 接受（版本 +1 并清除）| 拒绝（清除）| 版本前进后接受（`STALE_PENDING`，仍可拒绝）

**进阶规划（未实现）：**

- `ScreenVersion.change_source`：`manual_direct` / `builtin_rule` / `ai_patch`，与原有 `source.kind` 并存；版本树按来源筛选。
- 空间编辑提交生命周期：进入编辑态（本地暂存）→ 失焦/显式保存/离开编辑态（提交一次）→ 锁定校验 → 生成 `manual_direct` 版本。
- 三方合并生命周期：确定共同祖先 base → 逐字段比对 → 单方变更自动采纳 → 双方冲突进入 `MERGE_CONFLICT` → 用户选择 → 原子提交。
- 意图路由生命周期：显式短路 → 规则匹配 → 轻量分类器 → 大模型；每层记录 `route_layer` 与是否降级。
