## 3. 保存链路的校验顺序（API-018）

```text
assertWriter            → 只读成员 403 NO_PERMISSION
meta.locked             → 423 SCREEN_LOCKED
meta.pending            → 409 PENDING_EXISTS
meta.format=node-tree   → 422 MIGRATION_UNSUPPORTED（旧屏只读）
base_version 缺失/非法   → 400（detail.code=BASE_VERSION_REQUIRED）
base_version ≠ 当前版本  → 409 CONFLICT（附 current_version 与 hint）
validateScreenDoc       → 422 SCHEMA_INVALID（带 issues[].path）
frame.id ≠ 路径 screen_id → 422 SCHEMA_INVALID（MISMATCH）
丢失被引用的热区         → 422 INVALID_OUTPUT（附 lost_items）
写入版本                 → manual_direct，ai_cost=0，route_layer=manual
```

任一步失败都不产生版本，屏幕内容与版本指针保持不变。

## 4. Tidy 规则实现

| 规则 | 行为 |
| --- | --- |
| 顶栏贴顶 | 仅对 `appbar` / `nav` 族生效，整宽贴 `(0,0)` |
| 底栏贴底 | `frame.place` 为 bottom 时，栏类族贴屏底 |
| 内容流 | 自上而下、左对齐 16dp、组间距 16dp |
| 右边界 | 超出安全区时整组左移，不压缩尺寸 |
| 圆角 | 按项目形状映射 `{tl,tr,bl,br}`（square 0 / rounded 12 / full 半高） |
| 不参与 | 自由组、锁定组、锁定 Item；分隔线/进度/文本不写圆角 |
| 确定性 | 同一输入两次 Tidy，第二次 `changed_count = 0`（DC-038） |

| 2 | Tidy 把普通内容吸到 `(0,0)` | 卡片等非栏部件被当成顶栏 | 贴顶判定增加「栏类族」条件，并补回归用例 |

### 5.2 第二轮（接入编辑器岛后暴露的问题）

| # | 问题 | 影响 | 处理 |
| --- | --- | --- | --- |
| 7 | **`ready → load → ready` 消息回环** | 宿主持续下发 `load`、岛持续回 `ready`，1 秒内上万条消息，浏览器渲染进程被拖垮 | 宿主只在首次 `ready` 下发一次 `load`；岛对「同屏 + 相同 doc」的重复 `load` 只同步只读态、不再回 `ready`；外部回灌改用 `load{echo:true}` |
| 8 | 保存失败被归一为 `BRIDGE_PROTOCOL_MISMATCH` | 上层误判为协议错误，无法区分「协议不兼容」与「保存失败」 | 新增 `M3_ERR.BRIDGE_SAVE_FAILED`，保存失败进入 `error` 并保留草稿与版本 |
| 9 | 岛的屏在窄容器里被裁切 | 375/412 宽的屏装进 310 宽的侧栏，左侧被裁掉 85px | 岛内按容器自适应缩放；`#canvasWrap` 占位取缩放后真实尺寸（`transform` 不改变布局盒） |
| 10 | 面板 `renderTab` 重建 `innerHTML`，iframe 被连根移除 | 句柄仍指向已脱离文档的 iframe，岛「消失」 | `#islandMount` 独立于 `#designHost` 不参与重建；句柄增加 `mounted` 判定 |
| 11 | 部件未显式指定 `size` 时溢出屏宽 | Registry 默认宽 380 按 412 预设，375 屏里卡片右侧超出 43px 被裁 | 前后端布局都把默认宽夹到「屏宽 − 组横向偏移」，并补跨端一致性回归 |

> 第 7 条是本轮最严重的缺陷：它不会报错，只会让页面「越来越卡」，容易被误判成前端性能问题。已在协议文档补「回环约束」一节并用 `tests/m2-island.test.mjs` 固化为契约。

### 5.3 第三轮（用户反馈「新建页面无法使用 M3 设计功能」）

| # | 问题 | 影响 | 处理 |
| --- | --- | --- | --- |

| 13 | M3 文档进入生成链路即崩 | `countAll(cur.doc.root)` 对 M3 文档取值 undefined，所有基于新建屏的 AI 生成 500 | 新增 `nodeCountOf` / `anchorsOfDoc` 两个格式无关的辅助函数，替换 6 处直接读 `.root` 的代码 |
| 14 | 热区集合在两种格式下结构不同 | M3 返回对象、旧格式返回字符串，建边报错信息出现 `[object Object]`，自然语言建边 500 | `anchorsOfDoc` 统一返回 `{hotspot_id,item_id,slot,text,...}`；`hotspotsOf` 只取 id |

| 16 | 整屏替换的热区对比类型不匹配 | 字符串集合与对象集合比较，永远判定「丢失热区」 | 两侧都取 `hotspot_id` 再比较 |
| 17 | M3 锚点缺 `text` | 自然语言建边按文案匹配时 `undefined.includes` 抛错 | M3 锚点补 `text`（label + supporting） |
| 18 | 宿主加部件后未回灌岛内 | 「保存」发出的是岛内旧文档，宿主改动丢失 | `draftChanged` 调用 `reloadDraft`，岛用 `externalDirty` 标记非撤销栈来源的改动 |
| 19 | 徽标状态被重渲染重置 | 每次重渲都回到「加载中」，无法判断是否已保存 | 状态存入 `state.islandBadge`，重建 DOM 时恢复 |
| 20 | 选中屏幕后找不到「新建屏幕」入口 | 只能在画布空白节点或无选中态时新建 | 「属性」页签补「＋ 新建屏幕」 |

## 6. 浏览器端冒烟

真实服务 + 内建浏览器完整走通（最终代码）：

```text
打开项目 → 画布「＋ 新建屏幕」→ 填写名称 → 创建
→ 屏幕 format=m3、readonly=false、v1
→ 设计页签：编辑器岛 ready，部件面板 12 项，Tidy 可用，无「先转换」提示
→ 点「按钮」加入草稿 → 徽标「未保存」→ 岛内同步出现按钮
→ 点保存 → v2，徽标「已保存 v2」
→ 回查 GET /screens/:sid：current_version=2，items=[button]
```

关键量测（DOM / 接口实测）：

| 项 | 值 |
| --- | --- |
| 新建屏 | `format=m3`、`readonly=false`、`current_version=1` |
| 岛容器（iframe） | 310 × 518 |
| 屏体（缩放后） | 199 × 431，左右边距 56 / 55 |
| 应用栏 / 卡片右边缘 | 255 / 255，屏体右边界 255 |
| 保存前后 | v1 → v2，服务端与界面版本一致 |
| 旧屏转换 | 损失 0 项，可保存为 M3，`format` 变 `m3`、`readonly` 变 `false` |

## 8. 结论

M2 退出条件全部满足：

- ✅ 部件面板、图层、Tidy、撤销/重做、保存构成可用的手工搭屏闭环；

- ✅ 自由组坐标持久化，非自由组禁止 `Item.pos`；
- ✅ 编辑器、预览、导出共用同一渲染契约，布局零漂移；
- ✅ 190 例测试全部通过。
