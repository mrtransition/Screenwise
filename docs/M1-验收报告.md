## 3. 存储 v2 落地

### 3.1 目录与真源

```text
data/projects/<pid>/
├─ project.json            schema_version:2、design（权威主题）、design_tokens（投影）
├─ design-revisions.json   只追加，主题变更不递增屏幕版本
├─ canvas.json             屏幕坐标唯一源（ScreenMeta / ScreenDoc 不持有画布坐标）
├─ ui-state.json           编辑器 UI 状态
├─ flow.json               仅 screen_id + item_id + slot + 目标；不含 orphan
├─ measurements.json       文本宽度缓存，不产生版本
├─ history.json
└─ screens/<sid>/
   ├─ meta.json            format、status、locked、current_version、versions、pending
   └─ versions/v<n>.json   整文件 ScreenDoc 快照 + theme_snapshot
```

### 3.2 迁移命令

```bash
npm run migrate:v2 -- --dry-run          # 只读扫描，输出动作清单
npm run migrate:v2                       # 备份 → 原地迁移（失败自动回滚）
npm run migrate:v2 -- --restore <dir>    # 从备份恢复
npm run migrate:v2 -- --root <dataDir>   # 指定数据目录
```

### 3.3 导入通道

| 通道 | 上限 | 说明 |
| --- | --- | --- |
| `application/json` | 50MB | 普通请求体上限，超 413 |
| `multipart/form-data` | 50MB | 文件字段 `file`，可带 `name` |
| `{ file_path }` | 50MB | 服务端路径，不存在 404，超限 413 |

导入流程固定为「识别格式 → 校验 → 内存归一 → 写入」，任一步失败不产生项目/屏幕/边（DC-025）。

## 6. 期间修复

1. **`parseAnchor` 未定义**：`service.createEdge` 调用 `apps/web/src/screen-render.js` 的 `parseAnchor` 但未 import，导致全部建边接口 500，连带 10 个历史用例（AC-004/006、DC-001、预览路由、孤儿边、候选边、导出 4 例）失败。已补齐导入，151 例恢复全绿。
2. **`importIntoProject` 非原子**：建屏/建版本/写 flow 之间无补偿，中途失败会留下半个项目，违反 DC-025 与 AC-613。已改为 `try/catch`：失败时删除本次新建的屏目录、回滚 `flow.json`、还原 `screen_titles`，然后原样抛出。
